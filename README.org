* Fast-Twitch

Fast-Twitch lets ClojureScript applications use Ring handlers and middleware on
Node, Bun and Deno. It adapts native Fetch requests and responses to ordinary
maps, provides routing and middleware, and manages native server startup and
shutdown. Its client and server helpers also support TCP, WebSocket, SSE and
MessageChannel through configuration maps.

Start with [[file:examples/01-hello-world/][the hello-world example]], browse [[file:docs/API.md][the API docs]], or use
[[file:examples/07-native-transports/][the native transport examples]] for client/server exchanges.
This README introduces application usage, then explains the repository and
contributor commands. The API docs provide the function reference.

* Ring handlers, middleware and serving

A handler takes a request map and returns a response map. Middleware wraps the
handler. Serve the resulting application through ~ft-handler~:

#+begin_src clojure
(ns example
  (:require [fast-twitch.routing :as ft]
            [fast-twitch.middlewares.common :as middleware]
            [fast-twitch.macros :refer-macros [serve shutdown]]))

(defn handler [request]
  {:status 200
   :headers {"content-type" "text/plain"}
   :body (str "Hello from " (:uri request))})

(def app
  (middleware/wrap-response handler
    (fn [response _request]
      (assoc-in response [:headers "x-app"] "example"))))

(def http-server
  (serve :handler (ft/ft-handler app {:protocol "HTTP/1.1" :remote-addr "unknown"})
         :hostname "127.0.0.1"
         :port 6464))

;; When finished, (shutdown http-server) returns its native shutdown completion.
#+end_src

The existing ~routes~, ~ft-handler~, middleware and ~serve~ APIs remain
available. Request headers retain Fast-Twitch's lowercase keyword keys;
response headers use strings. Three-argument Ring handlers receive
~[request respond raise]~ when ~ft-handler~ or ~server/listen!~ has ~:async? true~.
Their return value is ignored; ~respond~ and ~raise~ deliver the result.

* Configured clients and servers

Use ~fast-twitch.client.core/request!~ for HTTP/SSE and ~connect!~ for TCP or
WebSocket/EventSource. Use ~fast-twitch.server.core/listen!~ to start HTTP/TCP
servers. Client ~send!~, ~receive!~, ~half-close!~ and reader functions work with
connections from either endpoint. Client ~close!~ closes connections; server
~close!~ also stops native listeners. Handlers and messages remain ordinary functions and data.

#+begin_src clojure
(ns example.json
  (:require [cljs.core :refer [await]]
            [fast-twitch.client.core :as client]
            [fast-twitch.server.core :as server]))

(def http-server
  (server/listen! (fn [request] (server/response (:body request)))
                  {:transport :http
                   :hostname "127.0.0.1"
                   :port 6464
                   :codec :json
                   :streaming {:max-bytes 65536}}))

(defn ^:async exchange! []
  (let [response (await (client/request!
                         {:url "http://127.0.0.1:6464/"
                          :request-method :post
                          :headers {}
                          :body {"message" "hello"}}
                         {:codec :json :streaming {:max-bytes 65536}}))]
    (:body response)))

(defn ^:async run-example! []
  (try
    (prn (await (exchange!)))
    (finally (await (server/close! http-server)))))

(run-example!)
#+end_src

HTTP defaults to ~:codec :native~, preserving native body streams. ~:bytes~,
~:text~ and ~:json~ collect bodies within the configured byte limit. JSON encodes
supplied request/response data; its map keys are strings. ~:request-init~ accepts
native Fetch options, and client middleware transforms request/response maps.

~reduce-stream!~ processes byte chunks, or incrementally decoded UTF-8 text with
~{:codec :text}~. It awaits each reducer call before reading again. Invalid or
incomplete UTF-8 rejects; owned readers cancel on failure or early termination,
and borrowed readers release their locks without cancellation.

TCP uses ~connect!~ and ~listen!~ with ~:transport :tcp~, ~:codec~ and ~:streaming~.
~send!~ writes data, ~half-close!~ ends writes, and ~receive!~ collects through EOF.
WebSocket uses ~:transport :websocket~ and event listeners. SSE uses
~client/request!~ with ~:transport :sse~ and ~:on-event~, or ~client/connect!~ with ~:transport :event-source~ for native EventSource.
Use ~send!~ and ~close!~ with the WebSocket handle returned by ~client/connect!~;
server WebSocket listeners receive their connection handle in callbacks.
~fast-twitch.server.sse/response~ constructs the pull-based SSE response.
See the executable transport examples for complete lifecycles.

* Runtime support

| Runtime | Native support |
|---------+----------------|
| Node    | HTTP server/Fetch, TCP, WebSocket client, SSE Fetch, MessageChannel |
| Bun     | HTTP server/Fetch, TCP, WebSocket client/server, SSE Fetch, MessageChannel |
| Deno    | HTTP server/Fetch, TCP, WebSocket client/server, SSE Fetch, EventSource, MessageChannel |

Clients also use the corresponding browser APIs where available. Node has no
native WebSocket server upgrade here: incoming Node upgrades return HTTP 501.
The shared WebSocket client uses the runtime's global ~WebSocket~ constructor.
[[https://nodejs.org/learn/getting-started/websocket][Node documents its native client]]; [[https://bun.sh/docs/runtime/http/websockets][Bun]] and
[[https://docs.deno.com/api/deno/websockets/][Deno]] provide the server upgrade APIs used by ~server/runtime/websocket.cljs~.
The Cloudflare example serves HTTP through the worker's Fetch entry point. ~resources/fast_twitch/runtime-profiles.edn~ records the tested versions
and capability checks. Use the pinned compiler in ~:native-test~ for modern
~:refer-global~, ~async~/~await~, ~#js~, ~cljs.proxy~ and checked keys.

* CSRF forms

~fast-twitch.middlewares.anti-forgery/wrap-anti-forgery~ validates submitted
tokens and persists the token in ~:session~. Render the Hiccup field through the
existing ~fast-twitch.util.anti-forgery/anti-forgery-field~ helper within the
protected handler. Custom ~:read-token~ receives ~[request options]~;
~:error-handler~ receives ~[request failure]~. These are the original hook
contracts, including when the wrapped handler uses Ring callbacks.

* Contributing

~src/~ contains the library. The remaining directories have these specific roles:

- ~resources/deps.cljs~ tells the ClojureScript compiler to load
  ~resources/fast_twitch/native_externs.js~. Those extern declarations preserve
  native API property names during advanced compilation; they are not executed.
- ~resources/fast_twitch/transport-catalog.edn~ describes supported operations,
  codecs and options. ~runtime-profiles.edn~ records tested runtime versions,
  capabilities and results. Both are descriptive metadata, not runtime
  configuration; application configuration is passed to functions as maps.
- ~dev/fast_twitch/test_runner.clj~ builds the native suite, or the browser
  bundle and companion server when passed ~browser~. ~compiler_fixtures.clj~
  compiles and runs macro-consumer checks. ~qualification.clj~ runs portable
  Clojure option-guard and macro-form checks. ~lint.clj~ configures clj-kondo
  from the pinned compiler classpath and runs it against maintained code.
- ~dev/fast_twitch/defaults_consumer.cljs~ checks existing middleware usage,
  including sessions, CSRF, multipart and Ring callbacks.
  ~websocket_client_consumer.cljs~ checks text/binary exchange, native identity
  and cleanup against a WebSocket endpoint supplied through ~FT_WS_URL~.
  These are development fixtures, not application startup dependencies.
- ~test/fast_twitch/integration/runner.cljs~ runs native transport and lifecycle
  regressions together with ~ring_contracts.cljs~ (Ring and CSRF behavior) and
  ~public_client_server.cljs~ (configured public API exchanges and guards).
  ~browser_runner.cljs~ exercises browser APIs; ~browser_server.cljs~ supplies
  its HTTP/SSE/WebSocket endpoints. ~test/fast_twitch/fixtures/static/fixture.txt~
  supplies file/resource middleware test data.
- ~test/fast_twitch/main_test.clj~ is retained starter scaffolding referring to
  ~fast-twitch.main~, which is absent. It is not part of the native suite or
  portable qualification runner.

Development runners and tests are loaded through aliases. Generated ~target/~
outputs and dependency caches are not source prerequisites.

#+begin_src sh
bb format
bb format --check
clojure -M:native-test
node target/native-tests.cjs
clojure -M:native-test advanced
node target/native-advanced.cjs
clojure -M:native-test:lint
clojure -M:native-test:compiler-check
clojure -M:native-test:portable-test
bb docs
#+end_src

~bb format~ uses repo-local zprint 1.3.0 and ~.zprintrc~; ~--check~ verifies
idempotent formatting. It formats maintained source, tooling and relevant
examples, excluding generated/vendor files and the separate Celld example.
The lint bootstrap reads the actual compiler dependencies. ~.lsp/config.edn~
selects the same classpath; reload the editor's language server after changing it.

Fast-Twitch uses Malli 0.20.2 for dynamic option validation. Shared schemas in
~fast-twitch.util.contracts~ describe reader settings and common native options;
transport-specific schemas stay beside their boundaries. Malli caches validators
for these schema objects. Native boundaries declare enforced function contracts
with ~mx/defn~. Boundaries retain ordinary ~^:dynamic~ declarations and native
~^:async~ bodies where needed; ~contracts/instrument~ applies their registered
Malli schemas once when the namespace loads. Port payload and transfer contracts are instrumented once at the native posting
operation. This preserves direct call emission with inline
arguments in the pinned compiler's advanced mode. There is no instrumentation
bootstrap for consumers. Malli errors retain schema paths and the operation,
without retaining argument payloads. Invalid arguments throw before I/O;
valid calls retain native results, Promise completion, settlement and cleanup.
Fetch validates transformed options at its actual native operation after request
middleware. Send options use Malli's function and sequence schemas. Close validates options
at the selected operation.

The existing ~serve~ macro rejects unknown literal option names and invalid
numeric literal ports during expansion. It leaves dynamic expressions and
app-derived values to execution. Native capability, connection state, incoming
data and streaming limits are checked where those results become available.
Checked keys verify required data access; they do not guarantee dynamic values
at compile time. Malli's argument parser does not support ~:keys!~, so required
checked destructuring belongs in function bodies when using ~mx/defn~.

The intentional oversized HTTP request runs separately:

#+begin_src sh
node target/native-tests.cjs http-limit-probe
#+end_src

It must print ~HTTP limit probe verified: {:status 500, :handled 0}~. Node and
Deno exit 0; Bun 1.4.2 exits 1 after its native server reports the expected request
error. The ordinary suite must exit 0 on every runtime. The same probe argument
works with ~target/native-advanced.cjs~.
